# Морской бой по сети

Многопользовательская веб-игра «Морской бой» в режиме реального времени.
Чистый JavaScript (Node.js + браузер), **без фреймворков и внешних библиотек**.
WebSocket реализован вручную по RFC 6455.

## Запуск

```bash
node server.js
```

Откройте `http://localhost:3000` в **двух вкладках** (или двух браузерах/устройствах).
Чтобы сохранять результаты, сначала **зарегистрируйтесь** (или войдите) — после
авторизации появится таблица ваших результатов. Далее нажмите «Подключиться».
Корабли расставляются автоматически по классическим правилам — они не касаются
друг друга (между ними не менее одной клетки, в том числе по диагонали). Игроки
стреляют по очереди (попадание — ход сохраняется, промах — ход переходит).

Порт можно изменить переменной окружения `PORT`:

```bash
# Windows (PowerShell)
$env:PORT=8080; node server.js
# Linux/macOS
PORT=8080 node server.js
```

## Структура

```
server.js          — HTTP-сервер + WebSocket (RFC 6455) + логика игры + авторизация + сохранение
public/index.html  — разметка
public/style.css   — стили
public/game.js     — клиентская логика
games.json         — создаётся автоматически, хранит состояние игр
users.json         — создаётся автоматически, хранит пользователей (пароли хешируются) и их результаты
```

## Протокол (JSON поверх WebSocket)

Клиент → сервер:

| Тип        | Поля                              | Назначение                            |
|------------|-----------------------------------|---------------------------------------|
| `register` | `username`, `password`            | регистрация                           |
| `login`    | `username`, `password`            | вход                                  |
| `restore`  | `authToken`                       | восстановление сессии по токену       |
| `logout`   | `authToken`                       | выход                                 |
| `results`  | `authToken`                       | запросить свои результаты             |
| `join`     | `name`, `token`, `authToken`      | вход / переподключение по токену      |
| `shoot`    | `x`, `y`                          | выстрел                               |
| `restart`  | —                                 | новая партия                          |

Сервер → клиент: `auth`, `results`, `joined`, `waiting`, `state`, `event`, `error`.

## Как выполнены требования

1. **Мгновенная синхронизация через WebSockets.** Каждый выстрел сервер
   обрабатывает и сразу рассылает актуальное состояние обоим игрокам.
2. **Только JavaScript, без фреймворков.** Сервер — чистый Node.js (включая
   ручную реализацию WebSocket), клиент — vanilla JS/CSS/HTML.
3. **Сохранение между запусками.** Состояние игр пишется в `games.json` после
   каждого действия и восстанавливается при старте сервера. Пользователи и их
   результаты хранятся в `users.json`: пароли хешируются (scrypt + соль), а после
   каждой завершённой партии результат записывается в таблицу игрока.

Дополнительно:

- **Конкурентный доступ / разрешение конфликтов.** Сервер — единственный
  источник истины: он валидирует ход (чей сейчас ход, не занята ли клетка) и
  отклоняет повторные/некорректные выстрелы, поэтому одновременные действия
  не приводят к рассинхронизации.
- **Восстановление после потери связи.** Клиент хранит токен в `localStorage`
  и при обрыве соединения автоматически переподключается, восстанавливая игру.
- **Деплой.** Приложение разворачивается как обычный Node.js-процесс (например,
  Render, Railway, Fly.io, Heroku); веб-сокеты подключаются к тому же хосту
  автоматически (`ws://` или `wss://` в зависимости от протокола страницы).
